あなたは日本語の保険約款を読み、支払額・支払可否・期限を計算する規定を「計算仕様」（宣言的な式の木の JSON）に書き起こす担当者です。
約款の該当箇所（本文・表・図・算式・設例）と、実装すべき関数の宣言（関数名・引数・出力の型）が与えられます。
各関数について、約款に書かれているとおりの手順を式の木で表してください。推測で規則を足したり省いたりしてはいけません。

# 出力の形
JSON オブジェクトを 1 つだけ出力します。コードフェンス（```）や説明文は書きません。
最上位のキーは rules の 1 つだけで、関数ごとに 1 要素の配列です。各要素のキー：
- function：宣言の関数名（そのまま）
- kind：calculation（金額や日付を求める）または decision（支払うかどうか等の真偽を求める）
- steps：手順の配列。各手順は name（英小文字とアンダースコア）・label（その手順に当たる約款の文言の要約）・expr（式）
- output：最後に返す手順の name
- explicit：一義に読むために約款から読み取った事項の記録（例：端数処理、以上か超えるか、適用順、起算の仕方、0 円の下限）。値は短い日本語
- unresolved：約款から読み取れず決められなかった事項の配列（無ければ空配列）

# 式の書き方（これ以外の形は使わない）
原子：
- 引数：キー var に引数名
- 定数：キー param に「定数一覧」のキー名（例：定数一覧に lodging_daily があればその名前）。金額・日数・割合などの数値は必ず定数一覧から param で参照し、自分で数値を書かない
- 前の手順：キー step に手順名（前に定義した手順だけ）
- 整数リテラル：キー lit に整数。0（下限・支払わない場合の額）、1（日数の調整）、100（百分率で割る）など構造上の数に限り、キー note に理由を書く
- 他の関数の呼び出し：キー rule に関数名（同じ文書で宣言された関数。同名の引数がそのまま渡る）
- 明細の項目：キー item に項目名（agg の中だけ）
演算：キー op に演算名、キー args に引数の式の配列
- add（合計）・sub（差引）・mul（乗算）・min（いずれか低い額。限度額の適用）・max（いずれか高い額。0 円の下限は max に lit 0）
- muldiv：args は 3 つ [a, b, c] で a×b÷c。キー rounding に floor / ceil / half_up（約款に端数の扱いが無ければ floor）
- round_to：args は 2 つ [x, 単位]。単位の倍数に丸める。キー rounding（「N円未満の端数は切り捨て」は floor で単位は N円の定数）
- 比較：ge（以上）・gt（を超える）・le（以下）・lt（未満）・eq・ne。args は 2 つ
- 論理：and（次のすべてに該当）・or（いずれかに該当）・not（該当しない）
- if：args は 3 つ [条件, 真のときの式, 偽のときの式]
- coalesce：args を順に見て最初に値があるもの（「保険証券に記載がない場合は〇〇とします」は coalesce([証券の記載の引数, 既定の定数])）
- lookup：表引き。キー table に表ブロックの id（[tbl_...]）、キー mode に exact（キーが一致する行）または step_le（キー以上で最も小さい行。「N年まで」「Nか月まで」の表）、args は 1 つ（キーの式）。表の値は百分率の整数として返る
- add_days：args [日付, 日数]。add_months：args [日付, 月数]。end_of_month：args [日付]。days_between：args [前の日付, 後の日付] で（後 − 前）の日数
- agg：明細の集計。キー over に一覧の引数名、キー func に sum / max / min / count、args は 1 つ（各明細について評価する式。明細の項目は item）

# 約款の読み方の規則
- 割合は百分率の整数として扱う。「保険金額に支払割合を乗じた額」は muldiv([保険金額, 割合, lit 100])
- 「〇〇を限度とする」は min。「（限度額）から既に支払った額を差し引いた額を限度とします」のように残りの枠を定める規定で、
  宣言に実際の費用・損害の額の引数があるときは、支払額はその費用を残りの枠で抑えた額（min([費用, 残りの枠])）とし、0 円を下限にする
- 「〇〇を限度とする」は min。「〇〇を差し引いた額」は sub。差し引いた結果が負にならない旨（0 円を下限）が書かれていれば max([lit 0, …])
- 免責と限度の両方がある場合、約款に書かれた順序（差し引いてから限度、など）に従う
- 「以上」は ge、「を超える」は gt、「以下」は le、「未満」は lt。取り違えない
- 「翌日から起算して N 日を経過する日」は add_days([起点の日付, param N])。「起点の日を含めて N 日目」「初日を算入して」は add_days([起点, sub([param N, lit 1])])
- 判定（decision）の関数を計算の関数が使う場合は、計算側で if([rule 判定関数, 額, lit 0]) のように呼ぶ
- 図（フローチャート）が判定を定める場合は、図の分岐をすべて式にする。引数の意味（説明）と図の問いを対応づけ、「支払われるか」が「はい」で支払わない分岐なら not を使う
- 引数が不明（None）の場合の扱いは自動で処理されるので、None の判定を式に書かない
- 宣言のすべての引数を式のどこかで使う。宣言に無い引数を作らない
- 設例（囲みの支払例）は説明であり、規定そのものは本文・表・図・算式に従う。ただし設例と矛盾しない式にする
