あなたは日本語の保険約款の「計算・判定の規定」を実装する関数の呼び出し口（関数の宣言）を点検して直す担当者です。
下の関数の宣言は、約款から一度設計したものです。機械的な点検で、下の「点検の指摘」が見つかりました。
約款の根拠の本文を読み直し、指摘が正しければ宣言を直してください。指摘が当たらなければ、宣言を変えずに返してください。
- function の名前と kind は変えない
- 根拠の本文と、下の「同じ条の本文と設例」に書かれていない入力を作らない。そこにある量・条件で、宣言に無いものだけを足す
  （設例は約款に印刷された本文である。設例が使う量は、関数が受け取れなければならない）
- 指摘ごとの直し方：
  - negated_requirement：指摘された入力を、行為が行われたかを問う肯定形の要件（exclusion なし）に書き換える。入力を増やさない
  - base_quantity_missing・example_quantity_unused：同じ条の本文（「〜の費用を支出した場合」など）や設例に現れる、支払の基礎となる量（支出した費用・損害の額など）を入力に足す
  - affirmative_condition_missing：除外事由に見える入力のうち、手続・医療の行為が行われないことを述べるものがあれば、それを肯定形の要件に書き換える。そのような入力が無く、本文にも要件が無ければ変えない
- 指摘に関係の無い入力は、名前も型も変えない
- 約款に印字された定数（限度額・日額・割合など）は入力にしない

# 関数の宣言の書き方
- function：英小文字と _ の名前（例 benefit_a_payout・benefit_a_eligible・claim_x_deadline。例の名前は形を示すだけで、約款の内容から名付ける）。額は *_payout、判定は *_eligible、日付は *_deadline で終える。文書の中で重ならない
- title：約款の文言で、何を求める関数か（例「後遺障害特別保険金の額」）
- kind：calculation か decision
- inputs：関数が受け取る事実。約款の計算・判定に使われる量だけを、約款に出てくる順に並べる
  - name：英小文字と _ の名前
  - type：int・bool・date・list のどれか（明細の集計に限り list）
  - unit：金額は JPY、日数 DAY、月数 MONTH、年数 YEAR、等級 GRADE、回数・人数 COUNT、それ以外（bool・date）は null
  - desc：約款の文言をそのまま使った説明（例「被保険者が入院した日数」「保険証券記載の保険金額」）
  - origin：claim_fact（事故・請求の事実）・assessment（損害の額などの査定）・policy（保険証券の記載）・computed（別の計算の結果）のどれか
  - nullable：true
  - exclusion：除外事由（該当すれば支払わない・対象外となる事由。本文の「〜の場合は支払いません」、除外事由の表の行、フローチャートで「はい」なら不支給に進む問い）の bool の入力にだけ true を付ける。支払の要件（該当すれば支払う条件）には付けない。迷うときは付けない
  - list のときは fields に明細の各項目（name・type・unit・desc）を書く
  - 判定の条件（本文の「〜の場合」「〜のときは支払いません」、フローチャートの各分岐の問い、○×の表の行と列）は、1 つずつ入力にする。
    はい／いいえで答える問いは bool、日数・金額・等級などの量と閾値を比べる問いは、比べられる量（int）を入力にする
  - 入力は「起きた事実そのもの」にする。関数の中で計算できる量は入力にしない：
    ・日数や期間は、元の日付（事故の日・入院を開始した日・責任開始日・書類を受け取った日など。type date）を入力にし、経過日数は関数の中で数える。
      ただし、約款が名前を付けて定義する量（「経過月数」「1か月未満の端日数」「治療日数」など）で計算・判定するときは、その量（int）を入力にする。
      日付を受け取るのは、日付から量を求める方法（起算日・「翌日から起算して」など）を約款が書いている場合だけにする
    ・「次のいずれかに該当する場合」の列挙や、条件を並べた表は、まとめて 1 つにせず、項目（表の行）ごとに bool の入力にする
    ・月と日の両方で数える期間（満月数と端日数など）は、それぞれを入力にする
  - 額の支払に条件（支払うかどうかの判定）が定められているときは、額の関数もその条件の入力をすべて受け取る（条件を満たさなければ支払わない額になる）
  - 入力にする条件は、その規定の条・特約（と、そこから明示的に参照される表・図・脚注）に書かれたものに限る。
    保険期間内の事故であること・約款全体に共通の免責事由など、すべての規定に共通の前提は、その規定の条が自分で定めていなければ入力にしない
  - 真偽の入力は、肯定形の事実にする（「〜しなかったか」「〜が行われなかったか」ではなく「〜したか」「〜が行われたか」）。
    約款が「〜しなかった場合は支払いません」のように否定形で書いていても、事実は肯定形で問い、否定は判定の式の中で表す。
    このとき exclusion は付けない（その事実が成り立てば支払う要件だから）。肯定形にした事実が成り立つと支払わない場合だけ exclusion を付ける
    「支払いません」の行や除外の表の行でも、支払の手続・医療の行為が行われないこと（「医師の治療を伴わない場合」「書面による届出が行われなかった場合」「承認を得ていない場合」など）を述べる行は、除外事由ではなく支払の要件である。その行為が行われたかを問う肯定形の bool（例 procedure_x_done「〜が行われたかどうか」）にし、exclusion は付けない。
    事故・損害の態様（「運転資格を有しないで運転している間」「他覚的所見が伴わない症状」など、起きた出来事の性質）は、否定の語を含んでいても除外事由のまま exclusion を付ける
  - 判定の関数は、支払わない事由（除外事由）だけでなく、支払う側の要件も入力にする。
    「書面により請求したとき」「医師の指示による」「届け出たとき」など、支払の要件として書かれた手続・事実は、1 つずつ bool の入力にする
  - 支出した費用・損害の額・実費に対して支払う規定（「〜の費用を支払います」「損害の額を支払います」）は、その費用・損害の額（int・JPY）を入力にする。
    算式が「限度額 − 既に支払った額」の形で書かれ、費用の額が式に出てこない場合も、支払う額はその費用を超えないので、費用の額を入力にする
  - 約款に印字された定数（限度額・日額・割合・待機の日数など）は入力にしない。関数の中で約款の値を使う
  - 「保険証券に記載があればその額、なければ約款の額」のように証券の記載で上書きされる値は、入力（origin policy）にする
- output：{"type": "int" | "bool" | "date"}
- units：根拠にした候補の id（候補に無い id を作らない。■ の条の id ではなく、その下の単位の id）
